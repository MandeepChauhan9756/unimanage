01 · System ka basic flow

Lead ka safar

Student pehli baar inquiry karta hai. Team uski need samajhti hai, sahi university/program suggest karti hai, aur application/enrollment tak follow-up karti hai.

NewNayi inquiry
ContactedPehli baat
CounselingOptions samjhana
ApplicationApply karna
EnrolledAdmission confirm
LostAage nahi badha

Team ka har step

  1. Lead aaya — website, referral, social, walk-in ya education fair se.
  2. Naam/phone aur jo study details maloom hon, record karo.
  3. Lead kisi counselor ko assign karo; next follow-up ki date set karo.
  4. Student se baat ke baad profile timeline mein update likho.
  5. Progress ke hisaab se stage update karo; agla reminder bhoolo mat.

CRM kya sambhalta hai?

  • Har inquiry ki ek searchable profile.
  • Counselor ownership aur student preferences.
  • Upcoming aur overdue follow-up ki list.
  • Stage change aur conversation history.
  • Dashboard par pipeline counts aur recent leads.

Daily use ka seedha tareeqa

Subah

Dashboard par overdue aur aaj ke follow-ups dekho. Apni lead list filter karo.

Har conversation ke baad

Call/email/WhatsApp/counseling ka chhota, useful note timeline mein likho.

Din ke aakhir mein

Stage aur next follow-up check karo. Kisi active lead ko bina next action mat chhodo.

Yaad rakhein: Lead mein email, city aur course preference optional hain. Pehli call se pehle jo details nahi milin, unki wajah se inquiry save karna na rokein.

02 · Screen-by-screen istemal

App ko kaise chalayein

Login ke baad admin aur counselor ko admissions workspace dikhta hai.

1. Login aur overview

Team account se sign in karein. Dashboard par total leads, new inquiries, counseling mein leads, applications, enrolled students aur overdue reminders ka count hota hai. Neeche follow-up queue aur recently added leads dekhein.

/login → /dashboard

2. Lead add karna

Add a lead par click karke required student name aur phone bharein. Email, city/country, study level, program, preferred university, intake aur counselor notes optional hain. Lead source, pipeline stage, counselor aur follow-up choose karke save karein.

Lead source: Website · Referral · Social · Walk-in · Education fair · Other

/leads/create → save ke baad student profile

3. Lead dhoondhna / filter karna

Leads list mein naam, phone, email, program ya university se search karein. Stage, source aur assigned counselor ke filters ek saath use kar sakte hain. Student row se poori profile khulti hai.

/leads

4. Profile, update aur timeline

Profile par phone/email, study interest, intake, source, current counselor aur next follow-up dekhein. Edit lead se stage, ownership, preferences aur reminder badlein. Timeline mein Call, Email, WhatsApp, Counseling, Application ya Other type ke saath note add karein.

/leads/profile/{id} · /leads/edit/{id}

5. Stage kab badlein?

New → Contacted: student se pehli baar baat/message ho gaya.

Contacted → Counseling: student ke goals/eligibility par guidance shuru ho gayi.

Counseling → Application: student ne application process shuru kar diya.

Application → Enrolled: university admission confirm hai.

Kisi bhi active stage → Lost: student aage nahi badh raha; context note karein.

Stage change profile timeline mein record hota hai.

Reminder: Follow-up date/time set karna reminder queue ko kaam ka banata hai. CRM reminder dikhata hai; email/WhatsApp notification khud se send nahi karta.

03 · Roles, modules aur permissions

Kaun kya kar sakta hai

Admin aur counselor admissions workflow sambhalte hain. Baaki roles existing university records modules ke liye rakhe gaye hain.

RoleAdmissions CRMExisting university areas
AdminLeads dekhna, banana, edit, assign, timeline updateStudents, departments, courses, subjects, faculty, attendance, timetable
Faculty / CounselorLeads dekhna, banana, edit, timeline update; assignment options mein faculty/admin accountsAcademic records, faculty list, attendance aur timetable access (route ke mutabik)

Security: login session + role filters ke peeche protected routes hain. Forms par CSRF protection hai. Mutating actions POST use karte hain; student status change aur logout GET link nahi hain.

Student name/contact aur counselor notes sensitive operational data hain. Har counselor ko apne kaam ke liye zaroori access hi dein. Shared/demo account ki jagah alag staff accounts banayein.

05 · Install, run aur troubleshoot

Setup checklist

Pehli baar chala rahe hain to in steps ko isi order mein follow karein.

Requirements

  • PHP 8.2 ya newer; project Composer/CodeIgniter 4 use karta hai.
  • PHP extensions: intl, mbstring, MySQLi (MySQL use karte waqt).
  • MySQL service on ho aur `.env` mein database connection sahi ho.
  • Apache use karte waqt web root project ke `public/` folder par point kare.

Local development

# 1. Project root mein env file copy karke values set karein cp env .env # 2. .env mein app.baseURL aur database.default.* set karein # 3. Database pehle create karein php spark migrate php spark db:seed InitialSeeder # 4. Local server php spark serve --host 127.0.0.1 --port 8080 # 5. Browser http://localhost:8080/

Is workspace ki current status

CRM schema configured MySQL database par migrate ho chuki hai. Local PHP CLI 8.5 par app verify hua. XAMPP Apache PHP 8.0.28 chala raha hai; CodeIgniter 4.7.5 ke liye PHP 8.2+ chahiye. Isliye XAMPP se chalane ke liye Apache PHP upgrade karein, ya development ke liye upar diya `php spark serve` command use karein.

Common issue → kya karein

Message / problemSolution
“PHP 8.2 or higher” / HTTP 503Active PHP check karein: terminal mein php -v; XAMPP Apache ka PHP version bhi 8.2+ hona chahiye.
“admissions_leads doesn't exist”Sahi `.env` database select karke `php spark migrate` run karein; `php spark migrate:status` se check karein.
Page login par redirect / DB connect errorMySQL start karein; `.env` host, database, user, password/port check karein. Secrets ko source control mein save na karein.
Wrong host/port ya redirectBrowser URL ko `.env` `app.baseURL` se match karein (scheme, host, port). Pretty URLs ke liye `indexPage` empty aur rewrite enabled ho.
Apache par route not found`public/` document root, `mod_rewrite`, `AllowOverride All` aur `public/.htaccess` verify karein.
Login successful, dashboard errorDatabase migrated ho aur admin/counselor user exist karta ho. Error details `writable/logs/` mein dekhein.
Demo users: `InitialSeeder` sample accounts banata hai. Deployment se pehle passwords badlein; sample credentials public/production mein use na karein.
Testing: vendor/bin/phpunit --no-coverage · Logs: writable/logs/06
06 · Abhi kya hai aur agla kya

Project ki current boundaries

Yeh guide current application ke implemented flow ko document karti hai; roadmap features ko available feature samajh kar plan na karein.

Abhi available

  • Admin/counselor authenticated admissions CRM.
  • Lead intake, edit, search aur stage/source/owner filters.
  • Counselor assignment aur student preference fields.
  • Follow-up date/time, overdue dashboard count aur queue.
  • Lead profile, stage-change history aur activity timeline.
  • Dashboard, responsive navigation aur existing academic screens.
  • Lead soft delete schema, CSRF protected forms, audit logging.

Abhi included nahi

  • Partner universities/programs ka searchable catalog.
  • Public website form ya external CRM lead API.
  • CSV lead import, deduplication aur campaign attribution.
  • Automatic WhatsApp/email reminders.
  • Application documents/checklists aur deadlines.
  • Enrolled lead se student record ka automatic conversion.
  • Advanced counselor conversion/response-time analytics.

Recommended build order

Phase A — Team setup: Individual staff accounts, secure password reset/change, role assignment aur counselor workload controls.
Phase B — University catalog: Partner university, location, program, eligibility, fee, intake aur deadline records; counselor ko verified options dikhana.
Phase C — Intake: Website form / approved import, consent, spam checks, duplicate detection aur source attribution.
Phase D — Application: Document checklist, application milestones/deadlines, status reporting aur enrolled lead ka student record se safe linkage.
Phase E — Automation & analytics: Approved email/WhatsApp provider integration, scheduled reminders, delivery logs aur conversion reporting.
Operational recommendation: Production se pehle real backup/restore test, private credentials, HTTPS, staff training, privacy/consent process aur admission-stage definitions approve karein.

Guide codebase ke current routes, screens, migrations aur setup instructions ke mutabik likhi gayi hai. UI label translation aur deployment details server configuration ke hisaab se badal sakte hain.
